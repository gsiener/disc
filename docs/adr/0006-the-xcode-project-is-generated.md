# ADR-0006 — The Xcode project is generated from `ios/project.yml`

- **Status:** Accepted
- **Date:** recorded 2026-08-10, decided earlier (see the note in `ios/project.yml`)

## Context

A `.pbxproj` is a machine-written file with a format designed for Xcode rather than for
readers. Committed, it produces merge conflicts that cannot be resolved by reading, and it
records absolute paths and build settings that drift per machine. In a repository where
several agents edit concurrently, it is the single worst file to share.

## Decision

`ios/Ultimate.xcodeproj` is **generated by XcodeGen** from `ios/project.yml`, and the
`pbxproj` is **not committed**. `xcodegen generate` runs as a step in CI before any build.

The spec writes a shared `Ultimate` scheme and a shared `UltimateUITests` scheme. Without
them, `xcodebuild` falls back to an implicit scheme with no buildables and rejects every
destination.

## Consequences

**What it bought.** The project is a readable, diffable, conflict-resolvable YAML file.
Concurrent agents can change targets without fighting over generated output.

**What it costs.** `xcodegen` is a prerequisite — `brew install xcodegen` in CI, and a fresh
clone cannot open the project in Xcode until it has been run once. A target added by editing
the project in Xcode is lost on the next generate; the spec is the source of truth.

## A related workflow decision, same file

The touch-test job **boots the simulator in its own step** and **compiles in its own step**
(`build-for-testing` / `test-without-building`) rather than letting `xcodebuild test` do
both implicitly. Both were learned from failures:

- A first simulator boot that happened inside the first test charged its cost to that test's
  timeout, and reported the failure as that test failing —
  `Application 'com.grahamsiener.ultimate' does not have a process ID` after 84 s, which reads
  as a crash in the app and was a simulator that had not finished coming up.
- Compiling inside the test step reported a *compile* failure as a *test* problem, and is what
  made `continue-on-error` look survivable (see [ADR-0005](0005-ci-never-cancels-on-main.md)).

**A step should be able to fail as the thing it is.** That is the general form, and it is why
these are separate steps rather than one convenient invocation.
